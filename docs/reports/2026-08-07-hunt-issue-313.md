# Hunt record — issue-313

## before-landing — stance 1: assume the rule as written cannot hold — find the state nothing maintains

Verdict: FINDING — `_migrate_legacy_ttl_marker()` was wired into `core_root()` but not into its documented read-only sibling `core_version()`, which falls through to the same managed clone dir and computes the same `git status --porcelain` dirty flag directly — so `core_version()` reports the legacy-marker "dirty" state forever if it's ever called before (or without) `core_root()` running in the same process.

### Reproduce
```python
import sys, os, subprocess, tempfile
sys.path.insert(0, ".")
import spawn

with tempfile.TemporaryDirectory() as tmp:
    ROOT = spawn.Path(tmp)
    spawn.ROOT = ROOT
    d = ROOT / "runs" / "rulebooks" / "tokenmaxxxer-core"
    (d / "core" / ".claude-plugin").mkdir(parents=True)
    (d / "core" / ".claude-plugin" / "plugin.json").write_text("{}")
    subprocess.run(["git", "init", "-q"], cwd=d)
    subprocess.run(["git", "config", "user.email", "a@b.c"], cwd=d)
    subprocess.run(["git", "config", "user.name", "a"], cwd=d)
    subprocess.run(["git", "add", "-A"], cwd=d)
    subprocess.run(["git", "commit", "-q", "-m", "init"], cwd=d)
    (d / ".muster-last-pull").write_text("123")  # pre-#297 legacy marker, left untracked in clone

    os.environ.pop("TOKENMAXXXER_CORE", None)
    os.environ.pop("TOKENMAXXXER_RULEBOOKS", None)

    print("core_version():", spawn.core_version())
```
`core_version()` never calls `_migrate_legacy_ttl_marker`, so it hits the legacy marker directly.

### Observed
`core_version()` returns `e663cef (커밋 안 된 변경 있음) (2026-08-07, on-the-record 클론)` — permanently "dirty" — even though the exact same clone, once `core_root()` runs (which does call the migration), reports `e663cef (2026-08-07, on-the-record 클론)` with no dirty suffix. `core_version()` is explicitly documented in-source as `checkout_version()` 의 core 쪽 대칭 (the read-only symmetric counterpart of core_root's dirty-string logic) and is used for per-spawn logging (`spawn.py:3014`) and the run ledger (`spawn.py:3348`) — i.e. it is meant to report exactly the same thing core_root's dirty check reports, but the fix only patched one of the two call sites reading that shared clone state.

### Expected
`core_version()` should report the same non-dirty status as `core_root()` once the legacy marker exists — either by also calling `_migrate_legacy_ttl_marker(d)` before computing dirty, or by centralizing the dirty computation so both functions read post-migration state. As written, any process/session that calls `core_version()` (e.g. for logging) before `core_root()` ever runs in that process — or in a role/tooling path that only ever calls `core_version()` and not `core_root()` — will keep reporting the pre-#297 in-clone marker as an uncommitted change forever, which is the exact silent-failure symptom issue #313 set out to fix, just left standing on this sibling path.
